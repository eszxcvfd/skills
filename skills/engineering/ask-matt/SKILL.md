# Ask Matt

Use this router when the next engineering move is unclear. The promoted
engineering surface includes the workflow skills and architecture disciplines.
Paseo role behavior lives in the machine-local profiles generated by
`/setup-matt-pocock-skills`, not in another project skill route.
Paseo owns lifecycle/workspace/control-plane state; the role profile or Pi
extension owns prompt/tool policy.

## Project routing

The project execution path is:

```text
task prompt → Supervisor observation (optional) → Lead → bounded Peer
```

The runtime profiles call the autonomous Lead `codex-root` (the legacy Codex
provider name) and the bounded executor `codex-peer`; the Pi equivalents are
`pi-lead` and `pi-peer`. The Supervisor is a governance observer, not an
implementation owner. It may start or watch Lead only when the human asks, but
adds no project command path, callback, or doctrine. Lead owns the coordination
method and may adapt it to the task; observation does not approve or micromanage
that method. Escalate only a material result deviation to the human.

Lead owns project scope, model/workspace routing, planning, integration, and
acceptance. Peer owns task-local engineering judgment inside one current-turn
V3 brief. Lead does not pass the Lead-only project contract (legacy Root-only
runtime contract) or hidden policy to Peer, and invalid/legacy briefs resolve
read-only.

## Andrew Ng comparison

Andrew Ng's agentic playbook contributes workflow patterns: reflection, tool
use, planning, and multi-agent collaboration. SLP contributes the governance
layer those patterns do not define: concern-specific authority, room ownership,
many-to-many workspace relationships, provenance, and reconciliation.

The earlier AI Transformation Playbook is an enterprise adoption guide, not a
runtime role topology. Use SLP to operate the work safely after the enterprise
has chosen its AI transformation path. The runtime contract lives in
`WORKSPACE_PROTOCOL.md`; it is the single source of truth for the role graph.

## Active routing

- First use in a repository → `/setup-matt-pocock-skills`.
- New autonomous project task, sequencing, delegation, integration, or
  acceptance → the configured Lead profile (`codex-root` in this adapter).
- One bounded implementation, research, review, proof, or cleanup packet →
  the configured `codex-peer` profile.
- Lifecycle observation or starting a fresh detached Lead outside the project
  → the configured `codex-supervisor` profile.
- Large, foggy effort spanning multiple sessions → `/wayfinder`.
- Fuzzy plan that needs a recorded interview and decision docs →
  `/grill-with-docs`.
- Architecture decision or unclear safe next step → `/architecture-council`
  (two independent proposers, then one combined challenge/verification/verdict
  pass; reduced mode uses peer/delegated workers and full mode retains legacy Paseo root agents for the Lead roles).
- Deep-module interface, seam, or locality question → `/codebase-design`.
- Domain terms, scenarios, glossary, or ADR decision → `/domain-modeling`.
- Aligned conversation that needs a durable spec → `/to-spec`.
- Finished spec that needs implementation slices → `/to-tickets`.
- Settled spec or ticket ready to build → `/implement`.
- Test-first feature or fix → `/tdd`.
- Broken, failing, slow, or regressed behavior → `/diagnosing-bugs`.
- Primary-source investigation → `/research`.
- Diff, branch, or PR review → `/code-review`.
- Active merge or rebase conflict → `/resolving-merge-conflicts`.
- Rare architecture-deepening scan with a visual report → the preserved misc
  `/improve-codebase-architecture` workflow.
- Incoming issue or external PR workflow → `/triage`.
- One-off manual setup or state transition → the preserved misc `/wizard`
  workflow.
- Design or state-model question needing a throwaway artifact → `/prototype`.
- Frontend/UI design, redesign, critique, accessibility, responsive polish, or visual iteration → `/impeccable`.

The normal small-work chain is:

```text
/grill-with-docs → /to-spec → /to-tickets → /implement → /code-review
```

Use `/architecture-council` before that chain when the change affects a
hard-to-reverse boundary or the safe next step is unclear. Use the generated
Paseo profiles when the work needs a detached Lead, bounded independent
execution, or lifecycle observation. Before each fresh agent route, verify the
provider/model/thinking against the target catalog and post-check
`get_agent_status → snapshot.runtimeInfo`; never silently fall back. Keep
observer concerns outside the project documents.
